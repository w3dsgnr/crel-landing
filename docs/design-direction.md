# Crel — дизайн-направление

Главный артефакт для созвона в четверг. Основа: `docs/refs-analysis.md` (анализ OnRamper /
Transak / логотипа) + `docs/brief.md` (итоги звонка). Решения помечены: **[решено]** — рабочая
рекомендация, можно строить; **[четверг]** — нужно слово заказчика.

---

## 1. Дизайн-токены сайта

База: язык логотипа c:rel_ (Space Grotesk, ч/б, острые углы, терминальная интонация) +
одобренная часть OnRamper (светлая витрина, крупная типографика, мокапы-фрагменты).
Лиловый подтон OnRamper (`#EFEEF3`) не берём — это их бренд-код; наши серые нейтральны.

### Палитра **[решено, кроме акцента]**

| Токен | Значение | Роль |
|---|---|---|
| `--bg` | `#FFFFFF` | базовый фон (наследие crel.ch) |
| `--bg-alt` | `#F5F5F7` | чередование секций, светлые карточки |
| `--bg-deep` | `#ECECEF` | второй шаг чередования, подложки |
| `--surface` | `#FCFCFD` | подложки UI-мокапов (всегда светлее карточки под ними) |
| `--ink` | `#111111` | текст, заголовки, залитые кнопки (из crel.ch) |
| `--ink-soft` | `#6A6A70` | вторичный текст, неактивные состояния |
| `--line` | `#111111` @ 12–16% | хайрлайны, обводки 1px |
| `--ink-invert` | `#FFFFFF` | текст на тёмном |
| `--accent` | **[четверг]** | см. вопрос №2; рабочий дефолт — акцент через инверсию ч/б |

Правило: цвет в контенте приходит только из UI-мокапов (как у OnRamper). Плоскости сайта — ахромат.

### Типографика **[решено]**

Единственный шрифт — **Space Grotesk** (подтверждён кодом crel.ch). Не моноширинный:
геометрический гротеск с CLI-акцентами в деталях знаков.

| Роль | Размер / высота строки | Начертание | Трекинг |
|---|---|---|---|
| Display (hero) | clamp(56px → 112px) / 1.0 | 700 | −2% |
| H2 секции | 40–64px / 1.05 | 500–700 | −1.5% |
| Заголовок карточки | 24–28px / 1.15 | 500 | −1% |
| Body | 16–17px / 1.5 | 400 | 0 |
| Лейблы / статусы | 12–13px / 1.2, строчные | 400 | +8…+12% |

Иерархия — размером. Лейблы всегда строчные (капс запрещён: строчность — часть бренда,
логотип печатается строчными).

### Сетка и ритм **[решено]**

- Контейнер 1200px, 12 колонок, гэп 24px; поля ≥ 48px desktop / 20px mobile.
- Вертикаль секций: 120–160px; заголовок секции ↔ контент: 64px.
- Чередование фонов секций: `--bg` → `--bg-alt` → `--bg` → тёмный футер. Без линий-разделителей.

### Геометрия и глубина **[решено, подтвердить в четверг]**

Острая шкала радиусов — от кнопок заглушки crel.ch (3px), против 24px-мягкости OnRamper.
Рифмуется со Space Grotesk и швейцарской базой:

- `--r-s: 2px` — чипы, бейджи-статусы;
- `--r-m: 4px` — кнопки, поля, тумблер;
- `--r-l: 8px` — карточки;
- `--r-xl: 12px` — подложки UI-мокапов.

Тени: у карточек — нет (разделение тоном). Единственная тень в системе — у плавающих
UI-мокапов: `0 24px 64px rgba(17,17,17,0.10)` — правило OnRamper «интерфейс парит».

### Motion-токены **[решено]**

Весь словарь движения выводится из печати (см. принцип 7):

| Токен | Значение | Применение |
|---|---|---|
| `--t-char-brand` | 210ms/символ | фирменный TextType hero-логотипа (idle-цикл с crel.ch) |
| `--t-char-fast` | 40ms/символ | перепечатка при переключении направлений |
| `--t-blink` | 850ms, `step-start` | мигание курсора (жёсткое вкл/выкл, без фейда) |
| `--d-quick / -base / -page` | 200 / 400 / 700ms | ховеры / появление блоков / смена состояния |
| `--ease-out` | `cubic-bezier(0.16, 1, 0.3, 1)` | появление (expo-out) |
| `--ease-swap` | `cubic-bezier(0.65, 0, 0.35, 1)` | смены состояний, каретка |
| stagger | 40–60ms | каскад карточек |

Грамматика курсора (с crel.ch, сохраняем): при печати/стирании курсор горит непрерывно,
мигает только в паузе. `prefers-reduced-motion` — мгновенная замена без печати.

## 2. Принципы дизайн-языка

1. **Швейцарская база, терминальная интонация — 90/10.** Девяносто процентов экрана — чистый
   гротеск, воздух, хайрлайны, ахромат. CLI-слой — приправа, не блюдо. Один CLI-акцент на экран.
2. **Двоеточие — структурный знак системы.** Лейблы секций (`01: platform`), статусные подписи
   (`status: mica_casp — in progress`), нумерация с ведущим нулём и ось переключателя.
   В H1/H2 контентных секций и в body двоеточие как приём не используется.
3. **Underscore-курсор — знак живого состояния.** Hero-логотип, активное слово тумблера,
   hover ключевых CTA (`get started_`). Не более одного мигающего курсора в вьюпорте.
4. **Иерархия — размером.** Два начертания, контраст масштабов (112px против 16px),
   никаких цветных заголовков и жирного в body.
5. **Продукт показываем фрагментом настоящего интерфейса.** Правило OnRamper: не скриншот
   целиком, а увеличенный фрагмент с реальными данными (числа, валюты, статусы KYC) на светлой
   подложке `--surface`, обрезанный краем карточки. Тень разрешена только мокапам.
6. **Плоскости разделяются тоном, углы — острые.** Секции чередуют фон, карточки плоские,
   радиусы 2–12px. Никаких градиентов, стекла, 3D — это территория «не брать» из анализа.
7. **Всё движение — из печати.** Словарь анимаций: type / erase / blink / caret-sweep /
   stagger-появление. Запрещены: bounce, parallax, 3D-повороты, глитч, scanlines. Терминальность —
   интонация паузы и курсора, не костюм хакера.

## 3. Концепция переключателя Services / Platform

Структурное требование заказчика: два равнозначных состояния лендинга, тумблер в духе
Transak Business/Individual, но переключение — фирменный приём Crel.

### 3.1. Ключевая идея: двоеточие как ось **[решено]**

`c:rel` читается как `key:value` — двоеточие уже делит бренд на «ключ» и «значение».
Переносим этот синтаксис на переключатель: двоеточие становится **неподвижной осью**, вокруг
которой меняется значение. Симметрия относительно двоеточия — визуальное доказательство
равнозначности направлений: форма тумблера буквально выражает главный бизнес-тезис брифа.

Синтаксическая система целиком:

- логотип: `c:rel_` — ключ бренда;
- тумблер: `services : platform` — ось между равными значениями;
- hero: `c:services_` / `c:platform_` — команда с аргументом (эхо состояния);
- лейблы секций: `02: licensing` — тот же знак на нижних уровнях.

### 3.2. Варианты исполнения тумблера

**Вариант A — «ось» в шапке** ⭐ рекомендуемый

Позиция Transak (сразу справа от логотипа, до пунктов меню — читается как «выбор мира»),
исполнение своё. Прямоугольник с обводкой `1px --line`, радиус 4px, внутри два строчных слова
и двоеточие-ось по центру:

```
[ services : platform ]      активное — --ink + курсор:  [ services⎯: platform ]  →  [ services : platform_ ]
```

- Активное слово: `--ink`, weight 500, с underscore-курсором после слова (горит статично,
  мигает только у активного состояния при бездействии страницы — опционально).
- Неактивное: `--ink-soft`, weight 400. Двоеточие всегда `--ink` — оно принадлежит системе.
- При переключении слова не двигаются: вес и цвет перетекают (200ms), курсор «перепрыгивает»
  к новому слову. Никакой скользящей пилюли — Transak-паттерн узнают именно по ней, у нас её нет.
- Шапка sticky → тумблер доступен всегда.

Плюсы: постоянная доступность; двоеточие-ось = равнозначность; ноль сходства с капсулой
Transak; тривиален на мобиле (те же два слова).
Риски: аффорданс — «это кликабельно?» Митигируется обводкой-рамкой, hover-состоянием
(курсор `_` подставляется к слову под мышью) и тем, что hero дублирует состояние крупно.

**Вариант B — «команда» в hero**

Hero-заголовок — гигантский `c:services_` / `c:platform_` (112px, TextType). Под ним или
рядом — пара слов-переключателей; клик перепечатывает аргумент команды прямо в заголовке.
Тумблер и заголовок — один объект.

Плюсы: максимально фирменно, вау-момент — сама точка входа; идеальная сцена для морфа.
Риски: недоступен после скролла (нужен дубль в шапке → два контрола, что и приводит к
гибриду с A); заголовок-неологизм требует смыслового подзаголовка-расшифровки
(«Swiss digital asset consulting» / «The digital asset rail for financial apps»);
на мобиле 112px-слово `platform` на грани.

**Вариант C — плавающий док**

Капсула fixed внизу по центру (или под шапкой), всегда в вьюпорте.

Плюсы: максимальная доступность, не конфликтует с логотипом.
Риски: app-интонация чужда швейцарской статике сайта; перекрывает контент на мобиле;
конкурирует с CTA за нижнюю зону; выглядит «виджетом», а не частью системы. **Отклонить.**

**Рекомендация: A + hero-эхо из B.** Канонический контрол — ось в шапке (всегда доступен).
Hero крупно показывает состояние командой `c:services_` и перепечатывается при переключении,
но кликабельный контрол — один, в шапке (клик по hero-команде — приятный бонус, не основной
путь). Это снимает риск двух конкурирующих контролов и сохраняет вау.

### 3.3. Анатомия переключения **[решено]**

Принцип: **общий каркас — сменная начинка**. Оба состояния — полноценные лендинги равной
глубины (5–6 секций), ни одно не является «главным».

| Слой | Общее (persistent) | Сменное (per-state) |
|---|---|---|
| Шапка | логотип `c:rel_`, тумблер, каркас меню, CTA-кнопка | якоря меню (ведут в секции своего состояния), текст CTA |
| Hero | композиция, сетка, пара CTA-кнопок | команда `c:services_`/`c:platform_`, подзаголовок-формула, текст CTA |
| Лента логотипов | слот и вёрстка | набор логотипов **[четверг №5]** |
| Контент | шаблоны секций (сетка карточек, табы, процесс) | все секции целиком, см. ниже |
| Финальный CTA | блок-оболочка | заголовок и действие (`talk to us_` / `get api keys_`) |
| Футер | credentials швейцарской компании, контакты, юр. полоса, комплаенс-бейджи | — (полностью общий) |

Карта секций (равный информационный вес):

- **services:** hero → `01: approach` (как работаем) → `02: services` (грид: внедрение,
  архитектурный консалтинг, лицензирование MiCA CASP/EMI/PCI DSS/AML/Travel Rule/KYC-KYB,
  vendor selection, мобильная разработка, сопровождение) → `03: licensing` (статусная подача:
  `status: mica_casp`) → `04: cases` → CTA.
- **platform:** hero → `01: capabilities` (грид: QASIS KYC, onRamp/offRamp, virtual accounts +
  dynamic IBANs, карты + Apple/Google Pay, seller terminal, widget + White Label API) →
  `02: integration` (развилка Widget vs White Label API) → `03: use cases` (табы: кошельки,
  обменники, необанки, ремитансы, пейроллы) → `04: partners` → CTA.

Скелет контента Platform — инвентарь Transak Business из `refs-analysis.md §2.1`;
подача capabilities — мокапами-фрагментами по правилу OnRamper, не иконками.

### 3.4. Хореография перехода — главный вау-момент

Три кандидата, терминология точная:

**Хореография 1 — «Перепечатка» (typewriter cascade)** ⭐ рекомендуемая

1. Клик по тумблеру: курсор в тумблере перепрыгивает, вес слов перетекает (200ms).
2. Hero-команда: аргумент стирается посимвольно backspace-анимацией на `--t-char-fast`
   (40ms/символ — быстрая «системная» печать, не брендовые 210ms: `services` уходит за ~320ms).
   **Двоеточие и `c` неподвижны** — ось работает и здесь. Новый аргумент печатается.
   Во время печати курсор горит, по завершении — один blink-цикл.
3. Контент: исходящие секции уходят каскадом «вниз-затухание» (translateY +12px, opacity → 0,
   120ms, stagger 40ms сверху вниз), входящие появляются встречным каскадом (translateY −16px → 0,
   opacity 0 → 1, 400ms, `--ease-out`, stagger 60ms). Секции — фон, hero-печать — солист.
4. Общий бюджет: ≤ 900ms до полной читабельности. Повторный клик в процессе — анимация
   скипается до конечного состояния (никогда не блокируем).

Плюсы: 100% фирменно — переход говорит грамматикой логотипа; технически надёжно (текст +
transform/opacity, без геометрической магии); изящная деградация (`prefers-reduced-motion` —
мгновенная замена). Риски: при частом переключении печать может утомлять → скип по повторному
клику и короткие тайминги решают.

**Хореография 2 — «Каретка» (caret sweep / clip-path wipe)**

Вертикальная линия 2px `--ink` (макро-версия underscore-курсора, повёрнутого в каретку)
проезжает по вьюпорту слева направо за 550–650ms (`--ease-swap`). Перед линией — старое
состояние, за линией — уже новое: два слоя, верхний срезается `clip-path: inset()`.
Как терминал перерисовывает строку. Hero-текст при этом меняется мгновенно на границе линии.

Плюсы: один непрерывный жест, читается как «система перерисовала экран», эффектно на видео.
Риски: в момент перехода в DOM живут оба состояния (двойной рендер — дорого на слабых
устройствах); при разной высоте состояний скролл-контекст под wipe прыгает; чисто исполнить
сложнее, чем кажется.

**Хореография 3 — «Перестройка» (FLIP shared elements)**

Общие структурные блоки морфят между состояниями по FLIP (First–Last–Invert–Play): карточка
«лицензирование» Services перелетает и перевёрстывается в «QASIS KYC» Platform, тексты
crossfade внутри контейнеров.

Плюсы: ощущение «единого материала», самый дорогой вид. Риски: реальных пар-элементов между
состояниями мало (контент слишком разный) — морф несвязанных блоков выглядит случайным;
хрупко в поддержке (каждая правка контента ломает пары). **Отклонить.**

**Рекомендация: хореография 1 как ядро + элемент 2 как деталь**: во время перепечатки hero
тонкая линия-каретка пробегает только под шапкой (полоса 2px на ширину вьюпорта, 400ms) —
намёк на полную перерисовку без её цены. Полноэкранный wipe оставить как усиление на будущее,
если захочется больше зрелищности.

### 3.5. Технические решения

**URL-стратегия [решено]:** `/services` и `/platform` — настоящие адреса. Оба состояния
пререндерятся статикой (SSG) — полный HTML для SEO и шаринга, у каждого свои
`title / description / og:*`. Переключение тумблером — `history.pushState` + клиентский морф
без перезагрузки; meta и `og:` обновляются вместе с состоянием. Прямой заход на любой URL —
полноценная страница. Оба URL в sitemap; `/` отдаёт дефолтное состояние с
`rel=canonical` на его полный адрес.

**Состояние по умолчанию [четверг №1]:** рекомендация — **`/` → services**.
Аргументы: (а) прямые заходы на crel.ch сегодня — рефералы на консалтинг, это действующее
ядро бизнеса; (б) поисковый трафик на продуктовые запросы («digital asset rail», onramp API)
всё равно приземлится на `/platform` напрямую — дефолт корня на него не влияет;
(в) Services-витрина сильнее подаёт швейцарскую идентичность (доверие для обоих направлений).
Контраргумент для четверга: если стратегия года — продавать Platform, дефолт должен
показывать продукт. Механика от решения не зависит — меняется одна константа.
Опция «запоминать последний выбор в localStorage» — предлагаю **не** делать на старте:
неожиданная подмена корня удивляет и усложняет аналитику; вернуться к идее можно позже.

**Скролл при переключении [решено]: сброс наверх.** Аргументы: (а) состояния — разный контент
разной высоты; сохранение позиции приземляет пользователя в случайную секцию чужого нарратива;
(б) URL меняется — ментальная модель «новая страница начинается сверху»; (в) хореография
задумана от hero: печать команды — первый кадр перехода, его нужно видеть.
Исполнение: если пользователь в пределах первого вьюпорта — скролл не трогаем (он и так видит
hero); если глубже — мгновенный (не smooth) сброс наверх в первом кадре перехода, замаскированный
стартом каскада: секции всё равно перестраиваются, прыжок не считывается как прыжок.

**Доступность [решено]:** тумблер — `role="radiogroup"` с двумя радио (или две ссылки с
`aria-current="page"` — решим в вёрстке); фокус после переключения остаётся на тумблере;
полная клавиатурная навигация; `prefers-reduced-motion` отключает печать и каскады
(мгновенная замена контента). Заголовок `<h1>` в обоих состояниях — смысловой (подзаголовок-
формула), команда `c:services_` — декоративный display-элемент с `aria-label`.

## 4. Открытые вопросы для созвона в четверг

1. **Дефолт корня `/`** — services (рекомендация, аргументы в §3.5) или platform?
2. **Акцентный цвет** — два пути: (а) радикальный ахромат — акцент через инверсию ч/б,
   цвет только в UI-мокапах (рекомендация: максимально швейцарски и уже работает на заглушке);
