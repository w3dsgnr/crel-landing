# Спека: слой v4 «светлый референс» — редизайн лендинга + изометрика услуг

Дата: 2026-08-08. Статус: одобрена по секциям в сессии, ждёт финального ревью файла.

## 1. Контекст и цель

Лендинг живёт на слое v3 «необанкинг» (зелёная семья pine→вольтаж→cyan, стекло,
цветные бенто-якоря grad-abyss/signal/halo). Заказ: перевести весь лендинг в светлый
стиль референсов todesktop-класса и заменить интерфейсные мини-мокапы в секции услуг
изометрической инфографикой из простых фигур.

Источник стиля: `docs/refs/todesktop/design.md` + `design-tokens.json` (анализ anydesign
от 2026-08-08, два скриншота). «Одна фишка» референсов — **предмет на серой сцене**:
белая UI-панель или простой объёмный предмет на плоской серой карточке, весь цвет несёт
один синий акцент, зелёный/оранжевый строго функциональны, фон сцены оживляют
микро-моно-текстуры.

## 2. Принятые решения (лог сессии)

| Вопрос | Решение |
|---|---|
| Порядок с Планом 2 (слияние секций) | Сначала визуальный редизайн на текущей структуре; План 2 — потом |
| Охват светлого стиля | Весь лендинг (hero, все секции, CTA, footer) |
| Акцентный цвет | Синий как в референсах (#2E7CF6); зелёная семья v3 уходит из активной палитры |
| Техника изометрики | SVG/CSS в коде, без генеративных растров |
| Анимации мокапов | Сохранить поведение и очередь MockupStage, перерисовать только кожу (принято по умолчанию — вопрос остался без ответа) |
| Цветные бенто-якоря | Буквально по референсам: все карточки — единая серая сцена, якорей нет |

## 3. Токен-слой v4 «светлый референс» (`app/globals.css`)

Слой v3 архивируется тем же порядком, что раньше «Заряд»/«Сдержанный».

- Поверхности: `--page #FFFFFF`, `--card-surface #F5F5F7`, `--panel #FFFFFF`,
  `--hairline #E4E4E7`, `--ghost #D6D6DB`.
- Текст: `--text #1D1D1F`, `--text-muted #6E6E73`.
- Акцент один: `--accent #2E7CF6` — интерактив, ссылки, фокус-обводка, курсор `_`,
  синие моменты иллюстраций. Cyan/вольтаж/terminal-green из активной палитры уходят.
- Функциональные: `--ok #34C759` (только «выполнено»), `--warn #FF9F0A` (точечное
  выделение). Никогда как декоративная заливка.
- Радиусы, лестница без промежуточных: `chip 8 / panel 14 / card 26 / pill`.
- Тень одна на систему: `0 8px 24px rgba(0,0,0,.06), 0 2px 6px rgba(0,0,0,.04)`.
  Носят панели и предметы внутри сцен; карточки-сцены всегда плоские, без рамок.
- Градиенты grad-abyss/signal/halo, стекло, glow, scene-bloom — удаляются.
- Гарнитура проекта сохраняется; шкала: титул карточки ~21px/600/лёгкий минус-трекинг,
  описание 16px/400/1.6, micro-mono ~11px/500/+0.08em.

## 4. Анатомия карточки — компонент `CardScene`

1. Иллюстрационная зона сверху (~55–60% высоты), `overflow: hidden`; панели могут
   кадрироваться краем карточки.
2. Центрированный титул.
3. Hairline-линия ~64% ширины по центру.
4. Центрированное muted-описание, ≤3 строк, ~55ch.
5. Фоновый слой micro-texture: тематические моно-символы цветом `--ghost`, только в
   иллюстрационной зоне, асимметрично, частично за срезом панелей.

Дисциплина цвета: 1–2 синих момента на карточку внутри иллюстрации; текстовая зона
всегда плоская и бесцветная.

## 5. Изометрика услуг (ServicesGrid, 6 карточек)

Интерфейсные мини-мокапы секции услуг (StatusChecklist, VendorCompare, OpsFeed,
WalletFragment) заменяются изометрическими сценами — по одной метафоре на услугу:

| Услуга | Сцена |
|---|---|
| Platform implementation | Слои-плиты собираются в стек на базовой сетке |
| Architecture consulting | Чертёжная плоскость: блоки-узлы, соединённые рельсами |
| Licensing and compliance | Ворота-рамки на пути, документ-плита проходит, штамп-галочка |
| Vendor selection | Ряд блоков-кандидатов, один приподнят и подсвечен синим |
| Mobile apps | Плита-смартфон, над ней парят виджет-плитки |
| Ongoing support | Конвейер-лента со статус-шайбами, одна зелёная «ок» |

Техника: inline-SVG, изометрия 30°, простые фигуры (плиты, блоки, пути, кольца);
объём — 2–3-стоповые градиенты граней + одна стековая тень под сценой; грейскейл-база,
1–2 синих момента, зелёный только как статус. Компоненты `components/isometric/*.tsx`.
Появление — CSS-анимация «сборки» при входе во вьюпорт, с уважением reduced-motion.

Четыре заменённых мокапа и их поля в `content/services.ts` не удаляем в этой работе —
их снимет План 2 (там же — судьба `MiniMockup`-диспетчера).

## 6. Перерисовка живых мокапов (7 штук)

RampWidget, KycFlow, CardDuo, SellerTerminal, IbanAccount, CodeSnippet + MockupStage.
Поведение, тайминги и очередь «один живой за раз» не трогаем. Кожа: белые панели
радиуса 14 со стековой тенью, синие акценты вместо cyan (кнопки, активные поля, курсор
печати), статусные чипы — `--ok`. CodeSnippet — синтаксис в референсной гамме
(синий/красный на белом). Micro-texture тематические: терминал — суммы, KYC — бинарный
дождь, IBAN — группы по 4 символа, код — номера строк.

## 7. Применение по секциям

- **Header**: белый, hairline-низ, синий фокус/ховер. Стекло уходит.
- **Hero**: печать команды и `_`-курсор сохраняются; терминал — белая панель со
  стековой тенью, курсор и выделения синие. CursorGrid (если остаётся) — линии `--ghost`,
  без glow.
- **Capabilities (01)**: бенто 6 ячеек остаётся; все ячейки — серые сцены `CardScene`;
  живые мокапы в новой коже; ячейка Widget/White Label API — изометрическая сцена
  «виджет-плита встраивается в чужую панель» вместо `gates.png`.
- **UseCases (03)**: pinned-скраб и табы сохраняются; цветные SCENES-плиты → одна серая
  сцена, табы различаются иллюстрацией и micro-texture; активный таб `--text` с синим
  курсором.
- **Integration**: белая код-панель (CodeSnippet в новой коже).
- **Approach**: PNG scan/rails/gates заменяются изометрическими SVG-сценами.
- **LicensingStack, Cases**: серые карточки по анатомии §4.
- **Partners**: монохромные лого.
- **FinalCta**: единственное место крупного синего — кнопка-акцент на серой сцене.
- **Footer**: светлый, hairline-разделители.
- **MagicBento**: spotlight/border-glow отключаются, сетка-обёртка остаётся.
- Reveal-анимации и Lenis не трогаем.

## 8. Рабочий процесс: скриншоты в чат (обязательное)

Пользователь ведёт сессию удалённо и не видит localhost. После каждого визуального
этапа (токен-слой, каждая перерисованная секция, каждая пачка изометрических сцен)
исполнитель обязан:

1. Снять скриншоты затронутых секций (dev-сервер через preview-инструмент
   `crel-dev`; съёмка — `scripts/shoot.py` либо скриншот браузерной панели; помнить,
   что вкладка превью живёт с `document.hidden=true` — анимации проверять синхронными
   маркерами).
2. Отправить снимки пользователю в чат файлами (SendUserFile) с короткой подписью,
   что на них и что изменилось.
3. Не считать визуальный этап завершённым до отправки скриншотов.

## 10. Критерии приёмки

- Тексты и копирайт не изменены; структура и порядок секций не изменены.
- `npx tsc --noEmit` и `npm run build` проходят; роут один: `/`.
- Текстовые пары держат WCAG AA (`--text`/`--text-muted` на `--card-surface`);
  синий не используется для мелкого текста (контраст ≈3.9:1 — только крупное/иконки).
- Один бренд-акцент на весь лендинг; цветных заливок карточек нет; тень только у
  панелей/предметов внутри сцен.
- Мокапы живут с прежним поведением; изометрика и появление сцен уважают
  reduced-motion.
- Скриншоты каждого этапа отправлены в чат (§8).

## 11. Вне охвата
